What the screen does not contain

No status branching. Every label, tone, transition and explanation lives in one lookup table, so the screens hold zero if (status === …). An unrecognised status from the server renders as itself rather than being coerced to "Pending" — the server is ahead of the console more often than the reverse, and mislabelling an order's actual state is worse than admitting we do not know it.

No dialogOpen boolean beside a chosenStatus string either. The write flow is one nullable value, because that pair admits open: true, status: null — a confirmation dialog asking the operator to approve nothing.

Rows are real links, not click handlers on a tr. Operators working a queue middle-click and open in new tabs; a div with an onClick silently does nothing and gives no sign that it will.

Three bugs this screen surfaced

All three were invisible to a green test suite, because jsdom has no stylesheet, no stacking contexts and no hit testing.

Sortable headers rendered in a different case from plain ones — the UA stylesheet resets text-transform on form controls and that reset beats inheritance, so the button inside a th ignored the uppercase. Only visible on a table that mixes sortable and unsortable columns, which this is the first to do.

The sticky header did nothing. Its scroll container was an unbounded wrapper that never scrolled, so the header rode off the top of the page with the rest of the table.

Region-level skeletons announced nothing while loading, leaving a screen-reader user unable to distinguish a slow table from an empty one.
